# Q4 实验组与五类对照

参照 Q3 的具名对照体系，固定最终算法，比较上一版 Q4、普查后清除、螺旋扫描、随机游走和已知位置参考。最终算法不重新调参；所有普通组只接收公开参数与实际协议回执。

| 组别 | 独立代码入口 | 选择名 | 定义 |
|---|---|---|---|
| 实验组：最终信息感知算法 | [experiment_informed.py](experiment_informed.py) | `informed` | 继承最终 `informed.py`：信息感知选点、辅助测量可见性筛选、联合路线与完整清除闭环。 |
| 对照：上一版 Q4 | [control_refined.py](control_refined.py) | `refined` | 继承已冻结 `refined.py` v3，去掉最终版的信息感知选点与可见性筛选，保留路线优化和完成证据。 |
| 对照：普查后清除 | [control_census_then_clear.py](control_census_then_clear.py) | `census_then_clear` | 原点、半径 998 米八点内环、约 1866.50 米十二点外环，共 21 站；固定优化访问顺序，每站全扫 20 频道，完成全部 420 次测量后再定位清除。 |
| 对照：螺旋扫描及方向覆盖补齐 | [control_spiral_scan.py](control_spiral_scan.py) | `spiral_scan` | 沿用 Q3 径向间距 1000 米、沿弧约 500 米采样的螺旋及 1800 米外圈；之后补齐 21 站方向覆盖布局中未访问的站点。每站扫描后定位清除已发现源，取得完成证据即停止。 |
| 对照：随机游走 | [control_random_walk.py](control_random_walk.py) | `random_walk` | 扫描站位于 1800 米圆盘内，步长 500 米，越界重抽方向；每站定位清除已发现源。最多 128 步，没有覆盖后备，耗尽时明确报告未完成。 |
| 特权参考：已知真实位置 | [control_oracle.py](control_oracle.py) | `oracle` | 仅离线取得全部真实位置，多起点最近邻与 2-opt 优化开放路线，直接清除，无测量。仍需实际成功回执和费用审计，不是严格最优下界。 |

前三种扫描对照通过 `control_scan_common.py` 共用最终 Q4 的定位、光学后备、辅助测量与预算保护。差异在搜索路径及何时清除；定位途中不增加未计划的未知频道扫描。普查组已有全部 21 站读数，因此利用累计观测定位是其策略的一部分。独立入口继承公共实现，避免复制算法后产生版本漂移。

Q3 七站只适用于其全向源覆盖假设，不能直接证明 Q4 中朝向外侧的定向源不存在，因此普查和螺旋作上述方向覆盖调整，额外移动与测量全部计费。盘内随机游走没有通用方向覆盖保证；实际源全部被清除时仍可能缺少排除其他频道的证据。已发现 16 个不同源时可按题设公开上限排除剩余频道。

Q3 旧 PPO 的输入与观测模型针对 Q3，当前没有经过 Q4 适配并验证的同等模型。本交付用真实的上一版 Q4 作消融对照，不把 Q3 权重直接标作 Q4 算法，也不纳入训练集或权重。早期 `adaptive`、`seven_grid` 仍可用作补充比较，但不混入本次六组主表。

## 同场复现与表格

在仓库根目录运行，不需要训练或新增依赖。与 Q3 相同，10、12、14、16 源各 20 场，每组共 80 场，六组共 480 次运行。

```powershell
python -m src.q4.compare --output runs/q4/comparison/q3_aligned_80 --seed 280000000 --counts 10 12 14 16 --cases-per-group 20 --noise spatial
python -m src.q4.comparison_tables runs/q4/comparison/q3_aligned_80/comparison.json --output results/tables

# 单独运行某组，指定新输出目录
python -m src.q4.compare --strategies census_then_clear --output runs/q4/comparison/census_only --seed 280000000 --counts 10 12 14 16 --cases-per-group 20 --noise spatial

# 严格重放：未完成的随机游走也必须逐动作忠实重现
python -m src.q4.replay runs/q4/comparison/q3_aligned_80/random_walk --output runs/q4/comparison/random_replay.json
```

场景种子为 280000000、280001000、280002000、280003000 各起连续 20 个。半径 1800 米盘内按面积均匀生成源位置，接收半径在 1000–1500 米均匀生成；一半为定向源，朝向均匀。测量为幅度不超过 1° 的固定空间误差场，读数量化到 0.01°。这是假设的离线分布，不代表官方分布。随机游走使用独立种子 `410000003 + 1000*源数组序号 + 组内场景序号`；控制器不读取真实源数、坐标、朝向、半径或误差种子。只有离线工厂中明确指定的 Oracle 分支可接收真实位置，官方入口没有 Oracle 选项。

比较记录目录必须不存在；其中本地保存完整动作、场景、配置和源码快照。若有未完成组，比较程序仍保存全部组结果，并返回退出码 1，随后仍可生成表格。发布到 `results/tables/Q4_实验组与对照组_策略比较表.md/.csv/.json` 的是紧凑结果，另有文件名包含策略标识的逐场 CSV；不提交原始轨迹、训练资料或过程归档。

## 指标口径

- 实际清除率：每场成功清除数 / 实际源数，组内平均后对源数组等权。
- 表中秒/源：每场全部虚拟成本 T / 实际源数 N，同样对源数组等权；未完成组标星，仅作为原始耗时，不能参与完整清除速度排名。运行记录另保留 T / 成功清除数，成功数为零时为空。
- 确认完成：真实源全部清除，控制器已取得完成证据，无异常，费用与清除回执审计通过。特权组的完成依据单独标记为已知源列表。
- 总时间：平均每场全部虚拟成本，CSV 另给全部场景累计时间；计入移动、测量、切频、失败与成功清除。程序实际计算用时另列，不替代题设虚拟时间。
- 场景一致性：各组种子、源数和完整场景 SHA-256 指纹逐项相等；保留失败场景，不能删掉后求平均。

方向覆盖和位置外包使用浮点计算与保守余量，不声称已实现有向舍入的完整区间认证。所有数字仅为合成离线实验；最终算法原有 140 场独立配对表保持原样，本次 80 场使用新的种子及四个源数组，不能把两表的总均值直接解释为版本提升或下降。
